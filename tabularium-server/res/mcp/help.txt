Tabularium MCP — a filesystem-like document store for AI agents.

Use it as the shared knowledge base per request: task documents, meetings, runbooks, and agent-to-agent notes — unless your operator specifies another store.

This server speaks the same JSON-RPC vocabulary as POST /rpc (see tool `methods` for parameters). By default, destructive operations (delete/move/rename directory or document, reindex), identity (**`whoami`**), and ACL/PSK admin tools (**`acl_*`**, **`psk_*`**) are **not** registered as MCP tools. Set **`mcp.full = true`** in server config only on a **trusted private** Tabularium host to expose those tools through MCP; otherwise use CLI or REST with appropriate permissions.

**Credentials (`X-Auth-Key`).** When **`[server].authenticate = true`**, every HTTP call to Tabularium (REST, **`POST /rpc`**, MCP streamable HTTP) must carry auth the server accepts: typically **`X-Auth-Key: <psk>`** with a key minted via **`psk_create`** (or another admin path), **or**, when **`[oidc]`** is configured, the configured assertion header with a valid JWT. MCP clients cannot rely on browser cookies — configure the MCP transport to attach **`X-Auth-Key`** on each tool request whenever the server is not fronted by a WAF that injects the assertion for you. **`[mcp].authenticate = true`** gates the MCP route the same way; **`whoami`**, **`acl_*`**, and **`psk_*`** (when **`mcp.full = true`**) need the same headers as **`POST /rpc`**.

When **`[mcp].authenticate = true`** and **`mcp.full = true`**, send **`X-Auth-Key`** or your WAF assertion header with MCP requests for authenticated tools; ACL admin uses **`whoami`**, **`acl_*`**, and **`psk_*`** mirroring POST `/rpc`.

**Three operations, do not confuse them:** **find** (tree walk) = locate files and directories by path or name in the tree, using repeated **`list_directory`** calls — there is no separate MCP “find” tool. **search** = indexed search across document bodies, file names, and descriptions. Optional **`kind`** is **`lexical`**, **`semantic`**, or **`hybrid`** (default **`hybrid`**). Lexical uses Tantivy; semantic requires a configured embeddings provider and populated semantic index. Hybrid combines both, falling back to lexical with an incomplete-search status if semantic search fails. Without semantic configuration, default search uses lexical search. **grep** = regex line matches **inside one document** only.

**append_if_not_contains** (`path`, `marker`, `content`) appends raw bytes only when `marker` is not already a **substring** of the UTF-8 body (same semantics as Rust `str::contains`). The file **must exist** (otherwise the call errors). Returns JSON `{ "appended": bool, "revision": string }` — use `appended` like the older boolean wire shape; `revision` is the post-call file token.

**Revision (UUID v4)** tags each **file** row for optimistic concurrency. It advances only on **writes** (content/metadata mutations such as put, append, touch_document on a file, describe on a file, rename/move file). Passive reads update **`accessed_at`** only via `get_document` / `stat` / listing — they **do not** change `revision`. Directories keep `revision` null. **`only_if_revision`** on **`put_document`** or **`create_document`** (with `force=true` when replacing an existing file) performs compare-and-swap: mismatch → **`RevisionMismatch`** (-32003); missing file when `only_if_revision` is set → **`NotFound`** (-32603). When present, **`only_if_revision` overrides `force`** for stale-write detection (force cannot bypass a revision mismatch).

**Force-guard for mutations.** Both **put_document** and **append_document** take an optional `force` boolean (default `false`). With `force=false`, an attempt to write to a path that already exists fails with `Duplicate` (-32002) — pass `force=true` only when you deliberately intend to overwrite (`put_document`) or append to (`append_document`) an existing document. The check-then-create is atomic at the storage layer (SQLite `UNIQUE` constraint), so two concurrent agents cannot both observe "missing" and both create. Use **create_document** when you specifically want strict-create with no force toggle.

**say_document** is the preferred operation for meetings, conversations, and task discussions: the server appends a markdown block and records the sender in the heading from **from_id**. The target document **must already exist** (create it first with **put_document** or **append_document**). Do not use **append_document** for chat-style lines; it records no sender. *Exemption note:* **say_document** always appends to an existing document and is the only mutation operation intentionally exempt from the `force` guard, because (a) it cannot create new documents (missing target errors), and (b) it operates exclusively in conversation/meeting contexts where appending is the explicit purpose. It is therefore not a side door for arbitrary mutation.

For agents and tools: do **not** prefix the nickname into `content` (e.g. don't start with `## Name`). Provide the nickname via **from_id** only; the server writes the header automatically.

The default document format is markdown.

For mathematics, Latex formulas allowed as $inline$ or $$block$$

**reindex** accepts optional **`kind`**: **`lexical`**, **`semantic`**, or **`hybrid`** (default **`hybrid`**). The first semantic indexing must be full (omit the subtree). Later document changes update the semantic index automatically. Explicit semantic operations fail clearly when semantic search is unavailable.

**Bounded search (P1).** Optional `limit` is 1..256 (default 256). `max_output_bytes` is 512..1048576 (default 65536), measured as compact UTF-8 JSON of the search payload, excluding JSON-RPC/MCP/HTTP framing. Whole hits are omitted rather than corrupting a quote. An oversized first hit can produce an empty, truncated response; increase the budget or narrow the query. `has_more` and `truncated` indicate omitted authorized results (no total count or pagination promise). They are separate from engine readiness/fallback status. Search ranks by relevance; ties are deterministic. Hits include exact `snippet`, `start_line`/`end_line` (`line_end` aliases `end_line`; legacy `line_number` locates the match), `revision`, and `modified_at` (Unix nanoseconds, technical modification time, not content truth/currentness). Lexical snippets are bounded to 768 UTF-8 source bytes; semantic chunks use configured bounds. A snippet may start/end within a line; slice returns the containing full lines. Send `expected_revision` to `slice` to detect changes since search (RevisionMismatch, -32003). Slice returns `text` and its source `revision`. Two calls are not an atomic snapshot.

Compatibility: MCP always returns the structured report. REST/RPC keep the legacy hit array when no bounds and no `with_status=true` are requested; supplying either bound opts into the structured report. REST additionally sends `x-tabularium-search-truncated`. Existing default bounds still apply to legacy arrays. All results and omission flags are computed after ACL/path filtering.
